# Js

## Single-file components
Write every SFC with `&lt;script setup lang="ts"&gt;` placed before `&lt;template&gt;`. No Options API, no scoped `&lt;style&gt;` blocks — style with Tailwind utilities in the template. Declare emits with the type-only generic `defineEmits&lt;{...}&gt;()`, never the runtime array form.

## URLs and forms come from Wayfinder
Build every internal URL from Wayfinder — `@/actions/...` for controller actions, `@/routes/...` for named routes. Never hardcode a path or call a `route()` helper. Submit with `&lt;Form v-bind="Controller.action.form()" v-slot="{ errors, processing }"&gt;`; reserve `useForm` for forms whose state is pre-populated and reactively edited, and use `router.&lt;verb&gt;(Controller.action.url(...))` for imperative one-shot actions.

## Tailwind styling with semantic tokens
Use only the semantic color tokens from `resources/css/app.css` (`bg-card`, `text-muted-foreground`, `text-fg-subtle`, `bg-bg-hover`, `text-success/warning/info`, `text-svc-*`) — never raw palette scales like `neutral-500`, and avoid `dark:` overrides since tokens are theme-aware. Merge conditional classes with `cn()`; accept a `class?: HTMLAttributes['class']` prop and merge it last. Reserve `cva` for `components/ui` primitives — `mm/` components use `computed()` variant maps.

## Toasts are server-driven
User feedback comes from the server via `Inertia::flash('toast', ...)`, rendered by the single global flash listener in `lib/flashToast.ts`. Call vue-sonner's `toast.*` directly only in `fetch`/stream paths that bypass an Inertia visit; ad-hoc JSON calls go through the shared `jsonRequest&lt;T&gt;()` helper (no axios).

## useHttp onError only covers 422s
Inertia's `useHttp` calls `onError` only for a 422 validation response. A 500 goes to `onHttpException`, a dropped connection to `onNetworkError`, and in both cases the returned promise rejects. Handle all three callbacks and `.catch()` the promise for every request whose failure must be visible. Otherwise state stays stuck (e.g. SubtitleItemDrawer left every operation disabled), nothing tells the user, and the rejection goes unhandled. Pest browser tests won't catch this: they record only window errors and console.* calls, not unhandled rejections or failed-resource messages.

## Byte sizes render through formatBytes()
Format every byte count with `formatBytes()` from `@/lib/format` (binary steps, whole numbers to MB, one decimal from GB, `"0 B"` for zero, `"—"` for a missing, negative or non-finite value). Never add a local size formatter; `tests/Browser/ByteFormatTest.php` pins the output.

## JSON requests come from @/lib/http
Ad-hoc JSON calls use `jsonRequest&lt;T&gt;()` and CSRF headers use `csrfToken()`, both from `@/lib/http`. A request that never gets an answer throws `NETWORK_ERROR_MESSAGE` ("Could not reach the server. Try again.") from there, never the browser's raw "Failed to fetch", so a toast may show `e.message`; a `useHttp` `onNetworkError` callback shows the same constant. Never import them from a composable (`useAiChat` used to host `jsonRequest`) and never read the `csrf-token` meta tag directly.

## Type-aware lint covers .ts files only
Oxlint runs type-aware (`lint.options.typeAware` in `vite.config.ts`), with type information from tsrs, the TypeScript 7 Rust port Vite+ bundles. It checks `.ts` files only; `<script>` blocks in `.vue` files get no type-aware rules, so `no-floating-promises` and the like never fire there. Correctness rules, the type-aware ones included, are errors (`categories.correctness`), so `pnpm run check` fails on them. Fix a finding instead of disabling it: `void` a promise nothing should wait for and `await` one the next step needs, narrow an `unknown` before turning it into text instead of calling `String()` on it, and type event payloads instead of reading `Record<string, unknown>` into template literals. Disable a rule on one line, with the reason, only for a genuine false positive. `typeCheck` stays off: it reports false TS2614 errors on type exports from `.vue` files, and vue-tsc (`pnpm run types:check`) stays the type checker.

## Confirm with useConfirm(), never the browser dialog
Ask before a destructive or costly action with `const { confirm } = useConfirm(); if (!(await confirm({ title, description?, confirmLabel, destructive }))) return;` — one `ConfirmDialog` is mounted in the app layout. Pass `destructive: true` for deletes, removals, unlinks, declines and blocklists. Oxlint (the `lint` block in `vite.config.ts`) bans the global `confirm`, `window.confirm`, `globalThis.confirm` and `self.confirm`. Browser tests click `[data-confirm-accept]` / `[data-confirm-cancel]` instead of stubbing `window.confirm`.

## Hover prefetch: sidebar leaves and library cards only
`NavMain` leaves and the Sonarr/Radarr/Whisparr library grid cards use Inertia's `<Link prefetch>` (hover, 75 ms delay); `app.ts` keeps prefetched pages 10 s (`defaults.prefetch.cacheFor`), because Inertia does not drop them after a write. Other links do not prefetch. A prefetch that lands on the current URL is applied at once, remounting the page and dropping its local state; Inertia's `router.prefetch()` refuses the current URL, and `PrefetchTest` pins that, so re-check it after an Inertia upgrade. A `NavItem` sets `prefetch: false` when its page, in its initial (non-deferred) props, reads an upstream service that is uncached or whose failures are not cached (Downloads/SABnzbd, Subtitles/Bazarr), runs heavy un-deferred DB aggregation (AI Usage), or dispatches work/has a side effect on GET (Seasonal Anime's bootstrap sync job). A browser test that hovers or clicks a prefetching card (its poster or link) must fake that title's detail endpoint, or the prefetch walks the factory host. A control over the poster (`BulkCheckbox`, open-in-Radarr) sits beside the card link, not inside it, so hovering or clicking it does not prefetch; fake the endpoint anyway if the test's pointer also crosses the poster. `tests/Browser/PrefetchTest.php` pins it.

## A link styled as a button is one anchor
Render a navigation that looks like a button as `<Button as-child …><Link :href>…</Link></Button>` (or `<a>` for an external URL, with `target="_blank" rel="noopener noreferrer"`): reka-ui's `as-child` merges the button classes and attributes (`v-if`, `data-*`, `title`) onto the single anchor. Never wrap a `Button`, `button`, checkbox or input in a `<Link>` or `<a>`. A control that must sit on a link-like card goes beside the link in an overlay (above). A `title` names an icon-only anchor only while it has no text content, so an icon link whose only text is a badge (the header's unread count) needs a text name: an `sr-only` label inside the anchor (`AppSidebarHeader`'s "Notifications"). `tests/Unit/Architecture/InteractiveNestingArchTest.php` scans every `.vue` outside `components/ui/`, and `LinkButtonNestingTest` checks the rendered pages and the header link's name.

## Focus after a dialog-confirmed bulk run
Call `focusAfterBulk()` (`@/lib/bulk`) after every successful bulk run, dialog or not. When focus is still inside a closing `[role="dialog"]`, it waits for the dialog to leave the DOM and for Reka's zero-delay focus restore, then moves focus to the enabled select-all that has a box (else the `h1`: on a phone the table's select-all is `display: none`) only if it fell to `<body>`. Do not add per-dialog `@close-auto-focus` handlers for this. Cancel is different: a dialog the compact bar's ⋯ (or phone primary) opens has no trigger, so it takes `@close-auto-focus="(event) => returnFocusToBulkMenu(event, '<desktop inline button>')"` (`@/lib/bulk`), which sends focus back to `[data-bulk-more]` on a phone. `focusPageHeading()` never scrolls. `SabnzbdBulkTest`, `GrabQueueBulkTest`, `ActionQueueBulkTest` and `BulkBarPhoneTest` pin it.

## Focus after a row ⋯ menu's confirm
A per-row dropdown item that asks with `confirm()` reads `const trigger = focusedMenuTrigger()` (`@/lib/pageHeader`) before asking and passes `onCloseAutoFocus: (event) => returnFocusTo(event, trigger)`: the app-wide dialog has no trigger, so Reka would restore focus to the menu item, which is gone by then, and focus would drop to `<body>`. When it is confirmed, take `rowMenuFocusKeeper(trigger, '<every row trigger selector>')` (`@/lib/bulk`) while the row is still there and run it in the `onFinish` of each visit that re-renders the list. Give that visit `preserveScroll: true`: the keeper focuses without scrolling, so a visit that jumps to the top would leave the focused trigger below the fold. If focus fell to `<body>`, it moves focus to the trigger at the row's old position: the row's own, else the next row's, else the page heading. Connections (`ConfirmDialogTest`) and the grab queue's `QueueRowMenu` (`GrabQueueBulkTest`) pin it.

## Counts render through formatCount()
Format token budgets, call counts and other whole counts with `formatCount()` from `@/lib/format` (fixed en-US grouping, "—" for a missing or non-numeric value). Never use `new Intl.NumberFormat()` / `toLocaleString()` without a fixed locale for text the server renders too: Node's SSR locale and the browser's differ, which prints two strings and trips a hydration mismatch. `tests/Browser/PoolBudgetFormatTest.php` pins it under a German browser.

## Pages refresh on broadcasts through live props
A prop that refreshes when a broadcast arrives is declared on the server with `Inertia::live()` or `->live()`, on a channel built by `App\Broadcasting\LiveChannels` (the event is passed by class name, the channel explicitly; a new scoped channel gets an auth rule no looser than the channel its event already used). The page needs no listener: `lib/liveTransport.ts` routes each channel and event through one `useWebSocket` lease and reports connection status. Inertia itself reloads only those props (throttled) and refreshes them once after a reconnect, from the transport's `onStatusChange`; never add reloads inside the transport. A hand-written listener that patches rows from payloads registers an `onReconnect` catch-up instead (see `.ai/rules/composables.md`). `useRealtimeReload` is gone; never reload from a broadcast with `router.reload()` in a page; the only hand-written reloads left are `onReconnect` catch-ups in patch-in-place composables.

A page whose props come from a service cache that webhooks clear (the Sonarr, Radarr and Whisparr libraries and title pages, the Seerr requests list) makes those props live on `WebhookEventProcessed`, never on `WebhookReceived`. `WebhookEventProcessed` fires from `WebhookEvent::markProcessed()` after the queued handler returned, so after its `bustAll()`; `WebhookReceived` fires when the webhook is stored, before processing, and a reload on it re-reads the stale cache. A title page uses a channel scoped to its service connection, so another connection's webhook does not reload it. `tests/Browser/LibraryLiveReloadTest.php` pins it.

## Touch targets: 40 px on phones and touch screens
Every `Button` size and every `Checkbox` carries the `touch-target` utility (`resources/css/app.css`): under `(width < 40rem), (pointer: coarse)` it adds a centred `::after` at least 40 px square, so a compact control keeps its look but takes a 40 px tap; desktop is unchanged. Give a hand-rolled interactive element that is smaller than 40 px the same class (the dashboard's Review queue link, the movie card's Open in Radarr link, the dialog and sheet close X); a native `<input type="checkbox">` cannot take it (an input has no `::after`): wrap a bare one in `<label class="contents touch:inline-flex touch:size-10 touch:items-center touch:justify-center">` (no box at desktop, a 40 px tap area on touch), and give a text `<label>` that already holds one `touch:min-h-10`; the sweep measures a native checkbox through its wrapping label. The same query is the `touch:` variant (`touch:h-10`), for when the control itself must grow. Two traps: an `overflow-*` scroller clips the `::after` to its padding box (and an `overflow-x-auto` strip of compact controls scrolls vertically unless it is `overflow-y-hidden`), so a control inside a strip is sized with `touch:` instead (`SegmentedControl`'s options are `touch:h-10 touch:min-w-10`); and two neighbouring targets need a gap of at least 40 − their size (12 px for a 28 px control), or the later one's `::after`, painted on top, takes taps inside the earlier one's own 40 px area — (40 − size) / 2 only keeps it off the earlier one's box — so size them with `touch:` (the series view toggles are `touch:size-10`) or widen the gap on touch only (`touch:gap-3` for `size-7` row actions). `TouchTargetTest` probes the tappable area with `touchTargetTappableScript()` and the neighbours with `touchTargetNeighbourScript()`, and `PhoneJobsTouchTargetTest` sweeps every control in `main` on the phone-job pages; its hover sweep only sees opacity, so never hide a control with `invisible`/`hidden` plus a `group-hover:` reveal either. Prove a hit area with `document.elementFromPoint()` just outside the visual edge, never with the element's rect (`TouchTargetTest`). Never reveal a control only on hover: add `max-sm:opacity-100 [@media(hover:none)]:opacity-100` next to `group-hover:opacity-100`. Every icon-only button has an `aria-label` (`IconButtonNameArchTest` scans every `.vue` outside `components/ui/`).
