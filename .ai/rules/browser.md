# Browser

## Browser tests: actingAs, visit, assertNoSmoke
Authenticate with `$this->actingAs(User::factory()->{role}()->create())` before `visit()`, resolve paths via `route($name, absolute: false)`, and open every flow with `->assertNoSmoke()`. Scope element assertions to `data-*` attribute selectors (`assertSeeIn('[data-x]', ...)`) so sidebar/layout text cannot satisfy them. Register every new page route in `SmokeTest`'s member/admin route-name datasets.

## Sidebar badge counters must always cache, or browser tests stall per-request
HandleInertiaRequests recomputes InterventionCounter/SabnzbdDownloadCounter/WantedCounter inline on every full page visit and prefetch (the lazy `nav` prop is skipped on partial reloads) when the cache is cold. A recompute reaching an unreachable factory host (e.g. sonarr.local — a .local mDNS name that stalls DNS ~4s per call, ~13s per request) used to leave the cache unwritten, so every page render re-walked the host until the 30s assertion budget was gone (broke ConnectionSubtitleCheckTagsTest and SmokeTest's root-folder test, 2026-08). Two guards now exist — preserve both in refactors: InterventionCounter negative-caches failures (FAILURE_CACHE_TTL, 60s); WantedCounter is kept warm by the scheduled `library:refresh-wanted-count` (every 5 min) and HandleInertiaRequests only calls its `warm()` on a cold cache and only for manage-library users — one request at a time under a short Cache::lock (others get the cached value or 0), non-retrying upstream calls, a failure with nothing cached writing a 60s entry; and the Browser beforeEach in tests/Pest.php pre-seeds all three counter CACHE_KEYs so browser tests never recompute at all (badge logic is covered by InterventionCounterTest / HandleInertiaRequestsTest / WantedCounterTest). Keep test Http::fakes scoped — never a '*' catch-all, it blanks the SSR POST.

## Live tests emit through echoEmitScript() after hydration
Tests broadcast through the null driver, so a live test hands the event to the page with `echoEmitScript($channel, $event, $payload, $minimumListeners)` from `tests/Pest.php`: it waits until that many callbacks are bound for the event on `private-{$channel}` and throws when they never are. Never emit through a file-local `window.Pusher` helper. Call `appHydratedScript()` before reading Echo's channels, hovering a prefetching link or clicking right after `visit()`: SSR markup satisfies DOM assertions before Vue has hydrated, and nothing has subscribed or bound until then. On a full `visit()` every consumer (layout toast, sidebar badges, the page) binds in one mount flush, so one listener is enough when any consumer will do. Pass the real count when the page's own listener must be bound too: a consumer that binds later (Watch History subscribes in `onMounted`, so it waits for 2 on `emby.activity`), a test that asserts the page's reaction (the Action Queue waits for 3 on `members.actions` for `ActionRequestStatusChanged`, 4 for `ActionRequestCreated`), or any emit after a client-side visit under the persistent layout, where the layout's listeners already exist before the page mounts. Pass `0` for an event nothing should handle (`WebhookReceived` in `LibraryLiveReloadTest`): the helper then waits for nothing and only throws when the channel is missing, so call `appHydratedScript()` before it.

## A posterless card shows its title twice
A `Poster` without a real image renders its `hint` as visible text: library and search cards pass `title.toLowerCase().slice(0, 12)`, and the calendar's full rows pass the whole title. Playwright's text match is a case-insensitive substring, so `assertSeeIn()` with text the hint also contains matches two elements and fails on strict mode — and a fake poster URL that fails to load fails at an unpredictable moment, so the failure is a flake, not a red test. Give fixtures a data-URI poster that loads (`bulkBrowserPoster()` in `LibraryBulkActionsTest`) or one that fails at once (`calendarBrokenPoster()` in `CalendarTest`), or a title longer than 12 characters, and scope title assertions to the title element (`[data-calendar-item-title]`, `[data-whisparr-title]`), never to a whole row or list.

## Fail an endpoint that only queues work with an in-app double
An endpoint that queues an `ActionRequest` (the Bazarr drawer's operation and upload) calls no upstream to fake into a 5xx, and its upstream reads are cached. To test the page's failure toast, bind a Mockery double of the in-app collaborator it calls — `$this->mock(ActionOrchestrator::class, fn (MockInterface $mock) => $mock->shouldReceive('dispatch')->once()->andThrow(new RuntimeException('…')))` — which the in-process browser server shares with the test, so Laravel answers 500 and `useHttp` reaches `onHttpException`. A test for behaviour that already exists has no red phase: prove it by deleting the page's failure handler once and watching it fail. `BazarrSubtitleCenterTest` does this for both drawer toasts.

## Keep tests/.pest/shards.json current
CI splits the browser suite into duration-balanced shards (the `tests` matrix in `.github/workflows/ci.yml`) using the per-class timings in `tests/.pest/shards.json`. A class missing from the file is dealt to shards round-robin, and that shard's log prints `The [tests/.pest/shards.json] file is out of date`. Refresh the file with `vendor/bin/sail composer test:browser -- --update-shards` and commit it: in the PR that adds, splits or renames browser test classes, whenever a CI shard log shows that warning, and when the shard legs' durations drift well apart. Pest writes the file only when the whole run passes, so rerun after a flake. Run it serially (never `--parallel`) so the timings match CI. Changing the shard count needs only the matrix edit, not a refresh.

## Phone width is a regression gate
`tests/Browser/MobileLayoutTest.php` visits every page route at 375x812 (`visit($url)->on()->mobile()`, resolved once — every call on the lazy `On` opens a fresh page) and fails on content past the screen, a primary action off-screen, an unnamed control, a hover-only control, two overlapping controls (`phoneOverlapScript()`), a scroller that scrolls by 1–12 px (`phoneScrollSliverScript()`, the mark of a `touch-target` `::after` overhanging its scroller) or text that runs past its box (`mobileLayoutClippedTextScript()`, which measures each text node's line boxes against its nearest non-inline box). Its touch test runs `phoneSmallTargetsScript()` over every page `PhoneJobsTouchTargetTest` does not sweep. `the phone gate classifies every page route` fails while a GET route behind `auth` or `auth:<guard>` is in no dataset and not in `mobileLayoutExcludedRouteNames()` (JSON, exports and redirects, each with its reason): add a row when you add a page. A page row is `[routeName, primary, deferred, parameters]`; a page only a flow reaches (set-password, the two-factor challenge, Security behind password confirmation) is a `[routeName, root]` row in `mobileLayoutFlowAuthPages()`, with its setup in that test. For a page row: give a detail route its parameters (a fixture created with an explicit id of 901 or more) and a card page the card list as its deferred hook, so the check measures content rather than an empty state. Measure with the shared scripts in `tests/Pest.php` (`assertScript(phoneOverflowScript(...), '')`); the touch sweep counts a native checkbox's wrapping `<label>` as its tap area. Never widen an exemption to make a page pass — fix the layout. An overlap is excused only when the smaller control sits wholly inside the larger one (a checkbox on a card link) or its scroller clips it away. Phone tests on pages with cards use the card hooks only: the table is `display: none` below `sm` but still matches a strict selector. Desktop tests keep the default 1728x1117 device.

## Orphaned Playwright servers are reaped at bootstrap
pest-plugin-browser starts `playwright run-server` as a child of the Pest process and only stops it when Pest terminates normally; a run killed by `timeout`, an interrupted command or the OOM killer, or one whose browser tests time out, leaves the server running under PID 1 (they once piled up to ~160 servers / 14 GB in the Sail container). `tests/Pest.php` therefore calls `Tests\Support\OrphanedPlaywrightServers::reap()` on every run: it kills only `playwright run-server` processes whose parent is PID 1 — a live run's server is always a child of its PHP process, so concurrent runs in other worktrees are never touched. Set `REAP_ORPHANED_PLAYWRIGHT=0` to skip it. The Sail services run with `init: true` so PID 1 reaps the Chrome processes those servers leave behind; recreate the containers (`vendor/bin/sail up -d`) after pulling that change.

## Fixtures pin the connection type
A factory that builds a related `ServiceConnection` on its own picks a random service type: a bare `ActionRequest::factory()` brings a webhook event on a connection of any type. When the random type is one a page looks up with `findActive()` (Prowlarr, for one), that connection can win over the test's faked one, its unfaked host fails, and the row fails or passes depending on run order. Give such a model its connection explicitly (`'webhook_event_id' => null`, or a webhook event on the test's own connection) and create every connection a page reads with its factory state and the conventional fake host.

## Page helpers have no native return type
Rector's `NarrowWideUnionReturnTypeRector` narrows a helper that returns a page to `Webpage`, but `visit()->on()->mobile()` hands back an `AwaitableWebpage` at runtime, so the narrowed helper throws a `TypeError`. Never return a page from a helper with a native return type: take the page as a parameter (typed `AwaitableWebpage|PendingAwaitablePage|Webpage`) or keep the page setup in the test body.
